## Project

Fresh Next.js 16 App Router project (React 19.2, TypeScript strict). Package manager: **npm**.

## Commands

- `npm run dev` — start dev server (Turbopack is default, no flag needed)
- `npm run build` — production build
- `npm run lint` — ESLint (v9 flat config). There is **no `next lint`** command in Next.js 16
- No test framework is installed yet

## Next.js 16 gotchas

- **Async Request APIs**: `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` are all async-only. Synchronous access is fully removed.
- **`middleware.ts` → `proxy.ts`**: Middleware file and export are renamed. Edge runtime is not supported in `proxy` — use Node.js runtime or keep `middleware` for edge.
- **`revalidateTag`** requires a second `cacheLife` argument (e.g. `revalidateTag('x', 'max')`).
- **`cacheLife` / `cacheTag`**: `unstable_` prefix removed. Import directly from `next/cache`.
- **`next/image`**: Several default changes (`minimumCacheTTL` now 4h, local IP blocked by default, query strings on local images need config, `imageSizes` no longer includes 16).
- **Parallel routes** require explicit `default.js` in every slot.
- **`next dev` and `next build`** use separate output directories (`.next/dev` vs `.next`).
- **Turbopack config** is top-level `turbopack`, not `experimental.turbopack`.
- **No `next lint`**: Use `eslint` directly. `next build` no longer runs linting.
- **No `serverRuntimeConfig` / `publicRuntimeConfig`**: Use env vars and `NEXT_PUBLIC_` prefix.
- Full upgrade guide: `node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md`

## Spec-driven workflow

This project uses a spec-driven development flow. Two skills are available:

- **`/spec`** — Creates feature specs in `specs/`. Ask clarifying questions, build the spec section by section, save as `specs/NN-slug.md` in Draft state. Never writes code.
- **`/spec-impl`** — Implements an approved spec. Validates state is `Approved`, creates a git branch `spec-NN-slug`, implements step by step with diff reviews, then merges and tags.

Specs live in `specs/`. Config is in `specs/.spec-config.yml` (controls auto branch creation). Template reference is at `.opencode/skills/spec/template.md`.

**Workflow:** run `/spec` to define a feature → review and set status to `Approved` → run `/spec-impl` to implement it.
